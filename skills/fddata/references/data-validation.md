# 数据与程序契约

## 运行环境与文件

使用可用的Python 3及openpyxl。优先调用`load_workspace_dependencies`取得环境；当前本机已验证环境为`/Users/chenyunzhe/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3`，使用前检查路径仍有效。程序直接从Skill的`scripts/`执行，共享模块`fddata_common.py`须与三个入口程序放在一起。

每次导出建立独立任务目录，保存运行记录、报告、页面筛选证据和实际数据。报告目录只保存本次相关JSON，程序会读取目录内全部JSON并识别单批报告；重复成功报告需先确认实际归属，不能混入同一清单。输出路径须全新，已有文件和`.partial`文件会使程序立即停止。

程序按Asia/Shanghai的本地时间解释日期，不转换时区。支持`YYYY-MM-DD`及`YYYY-MM-DD HH:MM:SS`。仅填写日期时，开始时间补为00:00:00，结束时间补为23:59:59。

原始15列依次为：id、生成场景、用户、企业、时间、输入、提示词、输出、配置项、耗时、扣点、状态、失败原因、下载状态、备注。字段变化时先核实实际含义，再更新程序。

## 筛选配置

未指定`--scope`时，单文件校验使用[默认筛选配置](default-scope.json)。自定义范围时，在任务目录保存实际`scope.json`，包含三个非空字符串数组：

- `customer_filter_ui`：页面实际选中的客户状态。
- `scene_selection_ui`：页面实际选中的场景。
- `allowed_export_scenes`：根据真实样本确认的对应导出值。

程序只能检查文件中存在的字段。客户状态及其他页面筛选仍须保存独立页面证据。不同报告的范围必须相同。历史报告缺少范围字段时，使用`build_manifest.py --scope`显式提供已经核实的范围。

## 单批核验

调用`validate_export.py`时提供：

| 参数 | 内容 |
|---|---|
| 第一个位置参数 | 实际xlsx路径 |
| `--expected` | 本批页面查询条数 |
| `--start`、`--end` | 本批真实筛选时间 |
| `--started-ms` | 点击本批导出时记录的毫秒时间；新任务应提供 |
| `--scope` | 自定义筛选配置路径，可选 |
| `--report` | 新的单批JSON报告路径，父目录须存在 |

程序重置工作表范围，完整读取数据，检查列结构、条数、时间、场景、配置项JSON和整行重复，计算SHA-256。相同id可以对应不同记录，保留这些记录。报告中的`seconds_to_file`依据源文件修改时间计算，仅在文件时间仍代表真实下载完成时间时解释为请求至保存耗时。

## 运行记录与清单

`runs.json`是数组，每次导出提交写入一项。以下字段取自当次实际操作：

```json
[
  {
    "start": "2026-09-10 00:00:00",
    "end": "2026-09-11 23:59:59",
    "count": 10811,
    "startedMs": 1794305563195
  }
]
```

示例来自历史批次，新的任务必须填写实际日期、页面条数和提交时间。未完成的尝试也保留在运行记录中；只有存在成功报告且唯一匹配的批次才进入清单。相同范围有多次尝试时，依靠报告中的`started_ms`匹配运行记录。

调用`build_manifest.py`时提供：

| 参数 | 内容 |
|---|---|
| `--runs` | 真实运行记录路径 |
| `--reports-dir` | 单批报告目录；省略时使用runs.json所在目录 |
| `--start`、`--end` | 完整目标时间范围 |
| `--expected-total` | 独立查询得到的完整范围页面总数 |
| `--weekly-ui-totals` | 连续分段的页面总数JSON，可代替或补充完整总数 |
| `--scope` | 为历史报告补充已核实的范围，或核对自定义范围 |
| `--output` | 新清单路径 |

完整总数和分段总数至少提供一种。分段文件为数组，每项包含`start`、`end`、`expected_rows`，连续覆盖整个目标范围。日期可以精确到秒，分段无需与下载批次相同。清单阶段检查日期连续、范围一致、源文件校验值和运行记录匹配；合并阶段按每条记录的时间核对分段实际数量。

## 合并与归档

调用`combine_exports.py`，依次传入清单路径、新的`.csv.gz`路径，可选`--archive-dir`指定归档目录。输出按时间排序，采用UTF-8 BOM CSV及gzip压缩。程序重新核验全部源文件，再完整解压读取输出，核对行数、时间顺序和逐行内容校验值。

输出`数据.csv.gz`时，验证报告为同目录的`数据.csv.validation.json`。成功报告包含总行数、每日数量、场景数量、状态数量、分段页面核验结果及文件校验值。

指定归档目录时：

- 归档目录须与源xlsx位于同一文件系统。
- 原始xlsx按实际起止时间命名，通过硬链接保存，不增加第二份文件内容。
- 写入新的单批报告和`清单名.archived.json`，更新其中的文件引用；原清单、原报告及源路径保留。
- 硬链接共享内容，源文件与归档文件均按不可修改的原始资料使用。
- 下载目录中的源路径可在最终验收后，按任务清理授权逐项检查和移除。程序不执行该项删除。

## 中断产物与保留

每次运行只生成一个合并文件和一份验证报告，归档只生成一组原始文件链接及相应清单、报告。不自动覆盖历史结果，不反复生成同范围副本。

失败时保留`.partial`文件与报错信息供检查。再次启动前，核实这些路径归属本任务且没有活跃进程使用；确认可丢弃后清理对应路径，再执行程序。正常完成后不应遗留`.partial`文件。

验收后保留有效原始数据、提取记录、最新合并结果及必要的一个旧版本。删除本次已无用途的验证副本，客户原始资料和用途未知的文件不纳入自动清理。
