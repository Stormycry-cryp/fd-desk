分析输入中的真实 Case，阅读提供的本地图片，结合全部提示词、修改步骤、结局、耗时和用户问题提出判断。

每个 Case 第一条记录的 inputs 是客户起始输入。images.references 标识图片所属 Case、步骤及输入或输出。超过六步的链提供首步、末步和首次下载步骤的结果图片，全部提示词仍然保留。视频图片是参考图或封面，只能据此判断画面；动作、节奏和完整视频质量缺少证据时明确说明。

clusters 按具体问题归类。每类提供真实 caseIds 作为证据，说明输入、指令和输出之间观察到的具体差异及可能原因；区分可见事实和原因推断。只能引用本次输入中存在的 Case 和 tags 中已有且适用该业务线的标签。没有足够问题证据时允许 clusters 为空。

perCase 恰好覆盖每个 Case，提供 good、ok 或 bad 初步评价、问题标签和便于人工确认的说明。这些是待用户确认的建议。现有手工评价和批注是上下文，保留人工表达。

headline 使用不超过四十个汉字的一句话，suggestions 最多三条，说明具体可执行的操作。回答用户问题并展示证据，不要求数字逐字出现在原始结果中，可以依据提供的数据计算差值、占比或比例变化。
